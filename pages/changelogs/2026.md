- Infrastructure Updates
- Storage mounts switching to autofs

**Specific Effects to CCR users:**  

**What changed?** 
The **/projects** and **/vscratch** filesystems now use automounting on most CCR systems. Rather than making every project and scratch directory available all the time, directories are made available only when they are accessed.  

**What does this mean for you?**  
**Directory listings such as `ls /projects` or `ls /vscratch` will no longer show all subdirectories.**  

Instead, you should navigate directly to your group's directory or reference it by its full path in web interfaces such as Globus. For example:
```
   cd /projects/academic/[YourGroup]  
   cd /projects/rpci/[YourGroup]  
   cd /projects/industry/[YourGroup]  
   cd /vscratch/grp-[YourGroup]  
```
Once you're in your project or scratch directory, commands such as `ls`, `find`, and other file operations will work normally.

**Where can I find my group’s directory paths?**  
In [ColdFront](https://docs.ccr.buffalo.edu/en/latest/portals/coldfront/), each storage allocation has the full path listed both in the “description” and under the “Allocation Attributes” section on the Allocation Detail page.  To access this information, navigate to your project and click on the folder icon next to the storage allocation you’re interested in.  You can also quickly access this on the home page under the “Allocations” section by clicking on the green “Active” button next to the allocation name.  Note that for those with access to many allocations, not all will show up on the home page.  

**What systems does this affect?**  
Login nodes, compile nodes, compute nodes, Globus.  **_Coming soon:_** OnDemand  

**Why was this done?**  
This change reduces unnecessary filesystem activity and helps improve overall system performance.
